## 二、修复前证据基线

### 2.1 A3S `read` schema

- Boyue 拒绝 `read` 工具参数根节点的 `oneOf`，返回 `invalid_function_parameters`。
- A3S 源码最小修复已移除根节点 `oneOf`，保留执行期“`file_path` 与 `files` 必须二选一”校验。
- 当前应用中的原生二进制是手工暂存的 6.6.0 补丁，尚未形成唯一版本的受控包。

### 2.2 grounding 包装解析

- 真实 `knowledge_search` 结果是 A3S `ToolResult`，MCP envelope 位于字符串化的 `metadataJson.mcp`，业务命中位于 `structuredContent`，文本兜底位于 `content[].text`。
- 当前 runner 只读取根节点 `hits`，日志因此显示 `hits=0 read=no`，并跳过 `knowledge_read`。

### 2.3 知识库页加载

- `GET /api/v1/assets/me/knowledge` 修复前返回约 111,044,004 字节。
- JSON 约 86,025,448 字符，其中 `metadata.commitDiffs` 约 85,462,599 字符，资产内累计约 1050 个 commit。
- 页面等待资产和 8 个附属请求全部完成后才从“正在加载知识库”切换为可用状态。

### 2.4 错误来源卡片

- 首次回答将 `asset://...md` 放在中文全角括号内，现有正则未在 `）`/`。` 处停止。
- 实际抽取路径吞入了后续正文，点击后请求错误 blob 并返回 404。
- 第二次回答的 URI 单独占行，在换行处正确终止，因此未复现。

### 2.5 新发现的手动压缩问题

- A3S 已能把 `/compact` 解析为 `CommandAction::Compact`，但对话运行时收到该 action 后没有执行压缩。
- 结果是 UI/调用方可以看到命令已处理，却不会缩短模型侧历史，也不会生成 `ContextCompacted` 事件；下一轮仍携带未压缩上下文。
- 自动压缩走另一条 admission 路径，因此该问题不会证明自动压缩失效，但手动与自动行为不一致。

### 2.6 旧应用桥接、首次配置误判与关闭残留

- 实际启动的是 `/Applications/InternShannon.app` 中 2026-06-29 的旧构建，内含 A3S 4.2.1；它仍返回约 111 MB 的知识库首屏响应。
- 旧原生进程退出后，内置 Node sidecar 仍以 PPID 1 监听 `127.0.0.1:29653`，后续应用可能连接到旧 API，形成版本桥接。
- `/api/v1/config` 的读取异常被 `seedFromBackend` 内层 `catch` 吞掉并当作成功；首次配置弹窗随后把空的 Provider/模型状态误判为“首次启动”。递归重试外层的 `finally` 还可能过早解析 `waitForSeed`。
- 旧构建把主窗口红色关闭按钮解释为隐藏窗口，没有结束 sidecar，因此用户还需要手动退出应用。

### 2.7 对话页 WASM CSP 错误与 CSV 读取假缺失

- 用户提供的控制台错误明确是 WebView CSP 不允许 WebAssembly 实例化；聊天渲染链路会预加载 hash/Markdown/ANSI 的 WASM 运行时，因而每次进入对话页都可触发。
- 原 CSP 仅允许 `script-src 'self'`，又不应将范围放宽为通用 `'unsafe-eval'`。
- 旧的分块读取直接拼接带重叠的字符块，会将 CSV 行截断或重复；`route_edges.csv` 因此曾解析出 151 行/133 个伪唯一 ID，而原数据实际为 131 条。
- 原检索只返回文本命中片段；当用户要求“盘点全部 CSV 数量”时，即使数据完整存在，模型也只能看到零散片段并误报缺失。

## 四、核心修改点

### 4.1 `read` schema 的 Boyue/OpenAI 兼容性

- 删除 `read` 参数 schema 根节点的 `oneOf`，根节点保持 `type: object`。
- 保留 `file_path`、`files` 两种输入能力，并继续在工具执行层强制“必须且只能提供一个”。
- 没有通过放宽执行逻辑规避 schema 错误，因此两者同时出现或都不出现仍会明确失败。

### 4.2 grounding 包装解析

- 只在 kernel runner 的知识库 grounding 边界增加归一化解析：支持真实 A3S `ToolResult.metadataJson -> mcp -> structuredContent`，也保留根对象、嵌套 `output`、`content[].text` 和字符串化 JSON 兼容。
- 真实本地调用确认 `session.tool()` 返回键为 `name/output/exitCode/metadataJson`，检索业务对象位于 `metadataJson.mcp.structuredContent`。
- 解析深度限制为 8，避免无界递归；解析后再读取 `knowledge_search.hits/tableSummaries` 和 `knowledge_read` 内容。
- 该改动不修改知识库数据，也不修改通用 MCP 协议实现，属于可独立评审和回退的最小修复。

### 4.2.1 grounding 范围与预算

- 会话中一旦用户明确指定“只使用知识库”，后续追问保持同一知识库作用域；用户说“停止/不再使用知识库”后立即停止自动检索。
- 每轮最多读取 6 个唯一来源，读取内容总预算 18 KiB，完整 grounding 封装总预算 32 KiB；超出时截断内容或丢弃低优先级 read，保持 JSON 有效。
- 排序首先匹配用户精确 ID，并优先让该 ID 作为 CSV 记录主键出现的原始表，再考虑包含该 ID 的场景覆盖表或说明文档。

### 4.3 来源卡片

- 引用提取遇到反引号、中文全角括号和常见中文标点时立即终止，不再把“）。文中……”吞入 `asset://` URI。
- 引用标准化增加最大长度、控制字符、反斜杠、非法 URI 编码、空路径段、`.`/`..` 和编码后路径穿越检查。
- 使用用户提供的首次错误回答和第二次未复现回答作为回归样本，固定两种排版均只能抽取合法资源 URI。

### 4.4 知识库首屏加载

- `/assets/me/knowledge` 首屏 DTO 不再携带 `blobContents`、`commits`、`commitDiffs` 等重型版本/内容集合；详细数据仍由已有专用接口按需提供。
- 页面拿到轻量主资产后立即结束整页 loading；来源、关系图、配置、任务和审计等附属请求在后台加载，单项失败只使用该区域的安全默认值。
- 主请求超时 15 秒，附属请求超时 10 秒，避免单个可选面板永久阻塞整个知识库。

### 4.5 手动与自动压缩

- `/compact` 现在会使用与自动压缩一致的模型准入、超时、取消、token 预算、历史替换、自动保存和 `ContextCompacted` 事件流程。
- 同时覆盖阻塞与流式对话命令；压缩失败会返回错误，不再被静默吞掉。
- 自动压缩原逻辑保持不变，并用打包后的真实 sidecar WebSocket 链路继续回归。

### 4.6 “受控本地 A3S 包”的含义

- “本机暂存版本”原指直接替换应用中的原生 `.node` 文件：它缺少唯一包版本、来源 revision、哈希和平台匹配证据，其他机器无法可靠复现，也不适合团队发布。
- 现在由脚本生成完整 `.tgz`，独立安装到 staging 目录；只有显式设置 `INTERNSHANNON_LOCAL_A3S_PACKAGE` 且采用 standalone staging 时才允许替换。
- staging manifest 记录包名、版本、tgz SHA、源码 revision、dirty 状态、平台和架构；启动前 verifier 同时核对 JS 包元数据、原生二进制和宿主平台。
- 正式团队发布仍需：清理 A3S 工作树、提交源码与测试 PR、由 CI 为全部支持平台构建并签发原生包、发布正式版本、在书小安更新依赖与 lockfile、移除本地 override 后完成全平台回归。当前 `.2.tgz` 仅用于本机离线验收。

### 4.7 启动配置、版本隔离与关闭退出

- 配置 seed 现在只有在 `/api/v1/config` 真正读取并应用成功后才返回成功；失败会在同一个迭代重试生命周期内继续尝试，不再由递归 `finally` 提前通知 UI。
- 首次配置弹窗只有在后端配置已成功加载后才判断资料、工作区和模型是否缺失；读取失败只提示配置加载失败，不再创建空 OpenAI Provider 或伪装成首次启动。
- AI 设置自动保存也只在 seed 成功后启用，避免用空的前端默认值覆盖后端配置。
- 当前原生启动器检测到默认端口由另一 InternShannon sidecar 占用时会阻止启动，不再复用旧进程或让两个版本写同一会话存储；无关进程占端口时仍可使用隔离的备用端口。
- 主窗口红色关闭按钮会先关闭托管 sidecar，再退出原生应用；应用退出事件仍执行兜底清理。

### 4.8 CSV 结构化读取、引用和 WASM CSP

- 表格型资源由 CSV/XLSX 解析器生成轻量 `tableSummary`，包含列名、主键、记录数、有界 ID 列表和完整 `asset://` 资源 URI。
- 统计/盘点型问题可一次得到 8 张 CSV 的可验证记录数；单个分块读取按完整行对齐并补 CSV 表头，全文读取直接使用索引抽取文本，不再拼接重叠块。
- grounding 提示要求“文件名 + 真实记录 ID + 完整 URI”；回答中记录 ID 作为可见文本保留，完整 URI 转为文件级可打开卡片。本轮不实现 CSV 行级深链。
- 桌面 WebView CSP 仅在 `script-src` 增加 `'wasm-unsafe-eval'`，保留对通用 `'unsafe-eval'` 的禁止。已从安装后原生二进制中确认该策略已编译进应用。
- standalone 构建收尾阶段不再将 `INTERNSHANNON_LOCAL_A3S_PACKAGE` 泄漏到 dist-only 清理子进程，避免误报失败和在源码目录残留 300+ MB 暂存资源。

## 十四、通用化 grounding 与结构化来源协议

### 14.1 修订后的实施方案

1. 搜索阶段显式请求表目录，目录最多处理 32 个 CSV；通过列名、主键、精确记录 ID 和声明/保守推断的关系选择来源，不再内置火灾项目的文件名、ID 前缀、领域关键词或计算规则。

  "tables": [
    {
      "path": "raw/sources/orders.csv",

      "relations": [
        {
          "column": "account_id",

### 15.5 边界情况验收

- 两个 `/context` 请求并发、后台状态先返回、旧请求超时后迟到、切换会话或断线：只能由当前请求 ID 和当前会话响应结算。
- 原生 `contextUsage()` 报错、仅返回分母或标记压缩后待刷新：必须回退到有界估算，不得无限 pending；模型有效上限缺失时才允许明确报不可用。
- CSV 包含引号、逗号、换行、目标 ID 位于非主键列、文件尾部或超出检索 chunk：仍按解析后的单元格精确匹配；不存在的 ID 只能进入 `missingIdentifiers`。
- 模型伪造 `K99`、为未读 ID 生成定位、输出残缺 `asset://…/file.csv`、完整 URI 指向 registry 外资源：不得生成可点击卡片，不得按文件名猜来源。
- 简单和复合问题均不得超过各自的来源数、read 字节和 grounding 字节上限；复杂度未命中时不能自动放大预算。
- 返回锚点损坏、超过 15 分钟、会话被删除或消息不存在：清理锚点并安全回到底部，不能卡死或跳到错误会话。

### 17.4 正常流程验收

1. 在历史长会话中停在中部，点击来源卡片后点“返回对话”：应回到原会话、原消息和近似原阅读位置；重复 20 次后不应再出现 listener leak 警告。
2. 在知识库页面继续打开其他文件后再返回：来源入口应是临时预览，普通用户主动打开的知识库标签仍可正常保留。
3. 将会话向上滚动：应出现圆形下箭头；点击后平滑回到底部并隐藏。短会话静态列表和长会话虚拟列表各测一次。
4. 用任意新知识库提出跨表复合问题：高置信关联表应在预算内被读取，回答可有多个正确来源卡片；正文不得出现裸 `asset://`、K 句柄或孤立 `]`。
5. 触发自动压缩：会话中先显示“正在压缩上下文”，完成后原位更新为且只显示“已成功压缩上下文”；压缩后继续精确知识追问，事实、记录 ID 和来源卡片仍应正确。
6. 对有真实 token 历史的会话执行 `/compact`，按同一提示顺序验收；随后执行 `/context` 并追问一条精确知识问题。

### 17.5 边界情况验收

- 浏览器历史不可用、锚点过期/损坏、目标消息删除或会话删除：回到对话根路由并失败关闭，不能留在知识库、跳错会话或无限重试。
- 快速连续点击不同来源、查询参数连续变化、短时间频繁前进后退：聊天路由不应重复挂载，滚动监听数量应保持稳定。
- 关联目录含多个同名表或低置信关系超过预算：只保留声明/高置信且按确定顺序选出的最多两个关联来源，不得突破总来源数与总字节数。
- 普通数字、时间、楼层数或人数：不能自动成为记录 ID；显式“记录 ID：18432”时仍可精确读取。
- 未知 K 句柄、未读记录、重复右括号包裹非法定位、歧义缩写 URI：不得生成可点击卡片，正文显示未验证或移除内部 URI。
- 压缩预测略高但原生层最终未压缩、任务失败、用户取消或断线：临时“正在压缩上下文”必须移除，不能留下虚假成功记录。

### 17.6 最大风险

最大的剩余风险是压缩开始状态需要在 SDK 只有“完成事件”而没有“开始事件”的情况下做前置预测。当前优先使用上一轮实测占用，以受控文本估算补上本轮输入；误判时在结果、失败、取消或断线处自动撤销，绝不显示成功。真实 Boyue 的分词与原生阈值仍可能在边界附近产生短暂提示，因此最终验收应覆盖阈值前后各一轮。

第二个风险是为关联表预留来源会挤掉得分较低但仍相关的普通命中。当前最多只预留两个声明/高置信关联表，且不扩大既有 6/10 个来源与 18/64 KiB read 预算；后续如需提高召回应先增加关系元数据质量，不能继续扩大上下文。

返回定位仍可能受 WebView 字体、窗口缩放和超长消息异步渲染产生少量像素偏差；验收目标是“同一条消息和近似阅读位置”。本轮没有提交 PR、没有覆盖安装应用，原生窗口视觉点击和真实 Boyue 手动压缩仍是统一提交前的最终门槛。

4. 模拟一次 429 后在同一模型重试；再由用户手动切到另一个模型。前者不得自动切模型，后者应在同一会话正常继续。
5. 分别触发自动压缩和 `/compact`，确认开始/完成提示、原问题续答、`/context` 更新以及压缩后精确知识追问仍有正确来源。
6. 在普通知识库编辑 Markdown 后 `Command+S`，确认成功提示和重开持久化；从来源卡进入临时知识库时应只读但可选择/复制。全程只显示浅色主题。

### 19.5 边界情况验收

- 修改或跨数据目录复用 cursor、翻页期间索引 revision/权重/资产范围变化：必须拒绝旧游标，不能静默跳页或混合不同索引代际。
- 两个 Sidecar 同时首次启动：签名密钥通过唯一临时文件、`fsync` 和 hard-link 原子发布，最终只读到完整 32 字节、0600 密钥；损坏文件不自动轮换。
- 512 个高相关候选：MMR 结果前缀与基准算法一致，不能长时间阻塞 WebSocket；超过 top 512 的候选按原确定序保留在尾部，仍可分页取得。
- 显式默认模型缺密钥且环境中存在另一个 Provider 密钥：必须针对显式模型失败；不存在默认模型时才允许使用环境默认值。
- 向量 ID 被跨来源交换、相同来源/chunk pair 重复、缺少一条 vector 或内容 SHA 不一致：整份向量索引失败关闭并使用安全检索路径。
- 授权拒绝、任务取消、连接断开、429、压缩失败和非法 agent-ui 指令后立即重发：不得残留 busy operation、伪成功提示或错误操作卡。
- 来源卡返回在展开全部、长虚拟列表、消息删除、锚点过期/损坏及连续快速点击下都不能跳错会话；无法恢复目标时才安全回到底部。

### 19.6 最大风险

最大剩余风险不是本机程序能否运行，而是 `sourceDirty=true` 的受控 SDK 仍是 macOS arm64 私人验收包：它可由当前源码树指纹证明来源，也会在本机严格失败关闭，但不是干净提交、跨平台 CI 和开发者公证签名的正式发行件。团队发布前必须把 A3S 改动整理到干净 revision，为所有支持平台构建正式包并完成证书签名/公证；不得把当前 ad-hoc 签名包当作外部分发件。

产品层面的主要剩余风险是真实 Provider 对复杂复合问题的遵循质量和本机 UI 的像素级交互。检索覆盖、预算续取、引用信任边界和会话释放已有自动与真实链路保护，但最终仍需用 Boyue/GLM 执行完整问题脚本，并人工点击来源返回、Markdown 选择/保存和长会话压缩。若失败，应按搜索、读取、coverage、Provider 输出、引用终结、卡片 UI 或 operation 生命周期分层定位，不能再通过扩大预算或自动换模型掩盖问题。
