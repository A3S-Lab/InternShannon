# 书小安知识库 01 完整会话真实验收门禁

## 结论与适用边界

本门禁用于验证 macOS 上已安装的书小安、受控 A3S SDK、个人知识库和真实 Socket.IO 会话链路是否共同满足火灾模拟项目的验收约束。它固定使用 `boyue/gpt-5`，禁止自动切换模型，只导入 14 个批准来源，并按 `01-会话问题脚本.md` 执行 28 个输入、9 个独立会话。

“相对完善”的通过口径为：

1. 预检通过；
2. 28 轮真实 Provider/Sidecar/Socket.IO 自动门禁全部通过；
3. 按 `02-人工验收与参考答案.md` 评分至少 90 分，且一票否决项为 0；
4. 在原生 App 内人工验证来源卡片可打开正确文件并定位记录 ID。

本门禁不宣称达到跨平台、所有知识库类型或消防专业安全认证。火灾项目是虚构数据，不得用于真实现场指挥。

## 28 轮真实链路门禁

真实运行会调用 Provider，因此必须显式给出 `--yes-run-real-provider`，并把报告写到正式数据与 App Resources 之外：

```bash
cd /Users/caozichen/Downloads/书小安/InternShannon-a3s-code-6.6
node apps/desktop/scripts/smoke-fire-evacuation-acceptance.mjs \
  --yes-run-real-provider \
  --timeout-ms 600000 \
  --report /Users/caozichen/Downloads/书小安/outputs/acceptance/fire-acceptance-real.json
```

运行时会：

1. 新建临时数据和工作区目录；
2. 只复制 Provider 运行所需配置，不复制正式会话、知识库、日志和缓存；
3. 从已安装 App Resources 启动 Sidecar；
4. 导入并同步重建恰好 14 个来源，要求全部为 `indexed`；
5. 建立 9 个明确固定 `boyue/gpt-5` 且 `followDefaultModel=false` 的会话；
6. 通过真实 WebSocket 串行发送 28 个问题；
7. 只自动确认只读知识工具，其他工具确认全部拒绝；
8. 每轮重读会话模型并对回答、工具、来源、检索覆盖和日志进行失败闭合检查；
9. 写入同名 `.json` 和 `.md` 报告，结束后关闭 Sidecar 并删除本轮精确的临时目录。

## 自动失败条件

任意一项出现即不通过：

- 任意轮未以 `succeeded` 结束，回答为空，或超过 10 分钟；
- 任意轮前后模型不是 `boyue/gpt-5`；
- 回答或日志出现“来源引用未验证”；
- 回答泄露 `asset://` 或 `[[K…]]` 内部句柄；
- 调用任何外部网络搜索工具；
- 在同一会话的首轮之后重复发起 `Skill` 子运行；
- 应完整 grounding 的回答明确为 `partial`；
- 高置信问题缺失关键记录 ID、路线核心或必需来源卡片；
- D-1 三个新会话未一致给出 `F10-C -> F10-S1 -> EXIT-W -> ASM-W`；
- 会话数、轮数、来源数或指纹与预检不一致。

单轮超过 3 分钟但不超过 10 分钟记为性能警告，不自动等同于功能失败，但必须在验收结论中解释。

## 人工验收

自动门禁通过后，仍需在原生 App 中完成：

1. 依据 `02-人工验收与参考答案.md` 逐项评分，记录总分和一票否决数；
2. 检查事实、路线、人员优先级、安全边界和未知项表达；
3. 点击 0-6 及其他轮次的 Markdown/CSV 来源卡片，确认文件和记录 ID 定位正确；
4. 确认同一文件没有因 XLSX 或其他副本重复出卡；
5. 从来源预览返回会话，确认回到原消息和近似原视口位置。

自动报告中的 `humanScore` 和 `vetoCount` 预留为人工结论字段。未完成人工评分时，只能记为“自动门禁通过”，不能记为“知识库相对完善”。

## 最大风险

最大的验收风险是把“安装包指纹通过”、“单元/模拟链路通过”或“预检通过”误写为“真实知识库已完善”。模型回答、检索策略、结构化引用和 UI 定位只有在同一已安装 App、同一受控 SDK、固定数据和固定模型的完整链路上全部通过，才能支持相对完善的结论。

次要风险是 28 轮真实 Provider 测试耗时且可能计费，所以脚本默认拒绝真实运行，必须由操作者显式给出 `--yes-run-real-provider`。
