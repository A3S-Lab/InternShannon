## 5. 当前核心实现

### 5.1 知识库搜索和精确读取

主要文件：

- `apps/sidecar/src/modules/kernel/application/knowledge-grounding-planner.ts`
- `apps/sidecar/src/modules/kernel/application/kernel-message-runner.service.ts`

行为：

- 复合问题拆分为有界信息分面，为每个独立分面预留来源位置；
- 在原有预算内为声明关系或高置信关联表最多预留两个位置；
- 精确记录 ID 优先，CSV 目标行可以从文件末尾读取；
- 返回 `searchCandidateCount/searchTruncated/nextSearchCursor` 和目录侧对应覆盖字段，模型可在同一会话明确续取剩余结果，不再把预算截断误判为“检索完成”；
- 分页游标绑定查询、资产集合、索引 revision、排序参数和页大小，并使用数据目录内持久化的 0600 密钥签名；同一数据目录重启可继续，不同数据目录或篡改游标失败关闭；
- 混合检索先对全局候选做确定性 MMR 排序再分页；top 512 使用增量冗余计算，避免宽泛查询长时间阻塞 Sidecar 事件循环；
- 向量记录必须和真实 chunk 的 ID、来源路径、chunk 序号及内容 SHA 全集一致，交叉绑定、重复、缺失或过期索引整体失败关闭；
- CSV/表格支持结构化过滤、聚合、排序和游标分页，全文检索与结构化查询共享 revision 一致性边界；
- 会话汇总和后续问题只复用持久化的结构化 `knowledgeSources`，不把历史模型正文当成知识事实；
- 搜索未命中表示“本轮未检索到”，不表示知识库中绝对不存在；
- 不通过无限增加来源数或读取字节数提高召回。

当前预算：

- 普通问题：最多 6 个来源、18 KiB read、32 KiB grounding；
- 复合问题：最多 10 个来源、64 KiB read、80 KiB grounding；
- 搜索结果上限 12，分面搜索最多 3 个。

### 5.2 引用和来源卡片

主要文件：

- `apps/sidecar/src/modules/kernel/application/knowledge-source-reference.ts`
- `apps/web/src/components/agent-page/chat/message-item.tsx`

模型只应看到服务端生成的 `K1/K2` 短句柄，不能依赖或输出内部 `asset://` URI。服务端负责：

- 将有效句柄转换为可读的文件名和经过验证的记录 ID；
- 输出结构化 `knowledgeSources` 供来源卡片渲染和历史恢复；
- 接受有限的全角括号、单层括号和文件名显示差异；
- 只有本轮来源、唯一匹配和实际读到的记录 ID 才能生成卡片；
- 未知句柄、虚构 ID、残缺 URI、歧义同名文件必须失败关闭；
- 裸露的 `asset://…`、孤立 `]`、`;`、`)` 等旧引用残片会被清理。

不要恢复“仅凭文件名猜来源”的旧逻辑。少一张卡片优于打开错误文件。

### 5.3 来源卡片返回会话

这部分自动化已通过，但仍需要在短会话、超长虚拟列表和原先已经打开知识库页面的情况下做人工点击验收。

### 5.5 `/context`、压缩和模型切换

- `/context` 使用应用模型的有效上下文上限，并显式传给 A3S；
- 没有实测 token 时使用有界估算，不能长期显示“正在计算”或无意义的 `0.0%`；
- 自动压缩和手动压缩开始时显示“正在压缩上下文”；
- 成功后只显示“已成功压缩上下文”；
- 压缩完成后自动继续原问题；
- 同一会话模型切换不得留下旧 active operation；
- **禁止自动切换模型**：显式会话模型或默认模型缺少密钥/不可用时针对原模型报错；即使另一个 Provider 或环境变量有密钥也不能代替；
- 只有用户显式选择另一个已配置模型时才重建会话运行时；当前用户已确认显式切换可以正常继续对话。

## 6. 受控 A3S Code：不得再次回退

Boyue 的 OpenAI 兼容接口拒绝工具参数根节点含 `oneOf/anyOf/allOf/enum/const/not`。官方 `@a3s-lab/code@6.6.0` 的内置 `read` 曾在根节点使用 `oneOf`，导致：

```text
Invalid schema for function 'read': schema must have type 'object'
and not have 'oneOf'/'anyOf'/'allOf'/'enum'/'const'/'not' at the top level.
```

当前修复：

- 根 schema 固定为 `type: object`；
- 保留 `file_path` 和 `files` 两种参数；
- “必须且只能提供一个”的约束由工具执行层校验；
- desktop、sidecar 和 lockfile 都直接依赖仓库内受控 tgz；
- standalone 构建必须使用 `--require-controlled`；
- 缺包、版本错误、tgz 哈希错误、原生二进制哈希错误或退回 registry 包时构建直接失败。

当前受控身份：

```text
version:       6.6.1-knowledge-complete.1
tgz sha256:    08919d86ebbb13ba847da1a99e8c70e406f4a3e792993bb3fa9b57c8bb428879
binary sha256: 726c77a4e65be5898a4b22192972272c87fd3d16ed2408af4bf4cd50bcc4207c
source rev:    7fa9a95e911f11274878be9fc45c5d219c83f446
source tree:   88790599d4b7b893e05820b7174131b87e533bf39a3f3668311637b0847c67a2
platform:      darwin-arm64
sourceDirty:   true
```

`sourceDirty=true` 意味着它只适合当前本机离线验收和私人仓库备份，不是团队正式发布件。正式发布前必须把 A3S 改动整理到干净源码提交，由 CI 构建全部支持平台，再发布正式版本。

每次重新打包后必须检查：

## 10. 常见故障定位

| 症状 | 先检查 |
| --- | --- |
| Boyue 报 `Invalid schema for function 'read'` | `/Applications` 包的 `controlledLocalA3s` 是否为空；运行进程是否仍来自旧包 |
| `already has an active operation` | 前一轮是否失败、取消或压缩未释放；先区分根因和重试后的次生错误 |
| 宽泛检索遗漏后续结果 | 检查 coverage `hasMore`、`nextSearchCursor`、索引 revision 和持久签名密钥；不得仅扩大单轮预算 |
| 配置模型失效后回答来自另一模型 | 属于禁止的自动切换；检查显式默认模型是否在环境变量 fallback 之前失败关闭 |
| 回答出现 `asset://…` | 模型 grounding 是否看到了 URI；引用终结层是否使用结构化来源；不能用文件名猜测修补 |
| 有事实但没有来源卡片 | 分开检查搜索、读取、模型句柄、记录 ID 验证、引用解析和 UI 渲染 |
| 返回会话位于底部或空白 | 检查 return `requestId`、目标消息渲染、虚拟列表稳定和锚点是否被提前消费 |
| `/context` 一直“正在计算” | 检查当前会话请求 ID、最新实测 token、估算回退和模型有效上限 |
| 压缩后不续答 | 检查 `context_compacted` 后 operation phase 是否回到 running，以及原请求是否仍在同一流中 |
| 切页面时误报修改运行配置 | 检查被动重挂载是否重复同步 system prompt；相同值应幂等 |

## 11. 不可突破的注意事项

1. 不联网补充火灾事实；测试回答只使用指定知识库和当前会话内容。
2. 不修改离线知识库文件来迁就检索结果，除非任务明确要求修订测试数据。
3. 不导入测试控制目录、答案或 XLSX。
4. 不按文件名、残缺 URI 或历史模型正文猜来源。
5. 不为了提高命中率无上限扩大来源数、read 字节和上下文预算。
6. 不把搜索未命中表述为知识库确定不存在。
7. 不在会话运行或压缩时被动重写模型、system prompt 或 permission mode。
8. 不认为“构建成功”等同于“应用已经覆盖安装”。
9. 不删除或回滚当前未提交改动；先保存 `git status` 和任务相关 diff。
10. 不提交 API Key、Provider 凭据、用户会话数据或本地绝对配置到 GitHub。
11. 当前受控 A3S 仅有 `darwin-arm64`；其他平台必须明确失败，不能回退官方 6.6.0。
12. 团队 PR 前必须把 `sourceDirty=true` 的 A3S 整理成干净、可复现的正式包。
13. 不自动切换模型；其他 Provider 有密钥也不能替代用户选定或配置的模型。
